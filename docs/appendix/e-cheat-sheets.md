## Platform

### 01 · [The JDK Landscape (8 → 26)](../01-platform/01-jdk-landscape.md)

- **Feature release every 6 months** (March, September) · **LTS every 2 years** since 17
- **LTS releases:** 8 · 11 · 17 · 21 · **25 (current)**
- **LTS is a vendor commitment**, not a JDK behaviour
- **All mainstream JDKs are built from the same OpenJDK source** — choose on support, not capability
- **GPLv2 + Classpath Exception = free, including commercial** — nearly every distribution
- **Oracle JDK is the exception** — read its current terms
- **Default choice: Eclipse Temurin**
- **Class file major = Java version + 44** — 52=8 · 55=11 · 61=17 · 65=21 · 69=25
- **`--release N`**, never `-source`/`-target` — `--release` also restricts the API
- **Pin the patch version** in images and toolchains
- **Run non-LTS in CI**, LTS in production
- **8 → 17 → 21/25**, never 8 → 25 in one step
- **`Runtime.version()`**, not parsing `java.version`
- **No separate JRE since 11** — use `jlink`

### 02 · [JVM Runtime Model](../01-platform/02-jvm-runtime-model.md)

- **`-Xmx` bounds the heap, not the process** — metaspace, stacks, code cache, direct buffers are extra
- **Containers:** `-XX:MaxRAMPercentage=70`, not a fixed `-Xmx`; container support on by default since 10
- **Metaspace is native and unbounded by default** — cap it; reclaimed per class loader, not per class
- **Class loading:** load → verify → prepare → resolve → initialise; **initialisation is lazy**
- **`ClassNotFoundException`** = explicit lookup failed · **`NoClassDefFoundError`** = missing at runtime **or a failed static initialiser**
- **Find the first `ExceptionInInitializerError`** — later errors say nothing
- **Class identity = name + loader** — same bytes, two loaders, `ClassCastException`
- **Tiers:** interpreter → C1 (~200 calls) → C2 (~10,000) → deoptimise on violated assumption
- **`made not entrant`** = deoptimised; a repeating cycle is a real signal
- **Escape analysis may make an allocation free** — measure before avoiding one
- **Code cache full = JIT disabled** — silent, severe slowdown, one log line
- **Compressed oops end near 32 GB** — a bigger heap can hold fewer objects
- **`jcmd` for everything** — `VM.flags`, `VM.native_memory`, `GC.heap_info`, `Thread.dump_to_file`

### 03 · [The Toolchain](../01-platform/03-toolchain.md)

- **`javap -c -p`** — what did the compiler actually produce; **`javap -v`** for the constant pool
- **`jshell`** — REPL; `/env --class-path app.jar` to load your own classes
- **`java Hello.java`** (11) · multi-file (22) · no class declaration (25)
- **`jdeps -jdkinternals`** — internal API use, with suggested replacements. Run before any upgrade
- **`jdeprscan --release N`** — deprecated APIs in use
- **`jdeps --print-module-deps`** → feed straight into `jlink --add-modules`
- **`-parameters`** — required by anything binding by parameter name
- **`-Xlint:removal,unchecked`** minimum; `-Xlint:all -Werror` on new projects
- **Declare annotation processor paths** — implicit processing warns on 21, disabled later
- **`@argfile`** for JVM options — diffable, reviewable
- **`_JAVA_OPTIONS` overrides the command line** — check it when a flag is "ignored"
- **Multi-release JARs** — the running class may not be the one at the JAR root

### 04 · [Builds, Release Flags & Preview Features](../01-platform/04-builds-and-preview-features.md)

- **Three separate decisions:** build JDK (toolchain) · target version (`--release`) · runtime JDK (pinned image)
- **`--release N`**, never `-source`/`-target`
- **Maven = nearest wins** (ties by POM order) · **Gradle = highest wins** — neither checks compatibility
- **Fix conflicts with `dependencyManagement` / `constraints`**, not a direct dependency
- **Import BOMs**, omit individual versions
- **Commit and use the wrapper** — `./mvnw`, `./gradlew`
- **Preview needs the flag three times:** compile, test, runtime
- **Preview class files bind to one exact JDK release** — never publish one
- **Keep preview behind a build profile** — removable in one commit
- **Pin plugin versions · no ranges · no SNAPSHOTs** — or the build is not reproducible
- **Declare annotation processor paths** — implicit processing is going away
- **Gradle `implementation` over `api`** — stops consumers compiling against your internals
- **Run the latest non-LTS in CI**, non-blocking

### 05 · [Migration Strategy 8 → 25](../01-platform/05-migration-strategy.md)

- **Step: 8 → 17 → 21 → 25** — ship each to production before the next; never 8 → 25 direct
- **~90% of the work is dependencies** — upgrade them first, while still on the old JDK
- **Assess before estimating:** `jdeps -jdkinternals` · `jdeprscan --release N` · dependency freshness
- **Three kinds of breakage:** removed (loud) · encapsulated (loud, late) · **changed defaults (silent)**
- **Silent ones to test:** CLDR locale data (9) · G1 default (9) · UTF-8 default (18) · TLS defaults
- **Java 11 removed the Java EE modules** — JAXB et al. become dependencies
- **Java 16 encapsulated internals · Java 17 removed `--illegal-access`**
- **`--add-opens` is a ticket** — argument file, comment, named library and target version
- **Separate the runtime move from raising `--release`** — keeps rollback a runtime change
- **Don't adopt new language features in the upgrade PR** — change one thing
- **Canary on GC pauses, footprint, and p99**, not just error rate
- **17 is the landing point** — ship it, run it, then continue

## Language

### 06 · [Lambdas & Functional Interfaces](../02-language/06-lambdas-functional-interfaces.md)

- **Functional interface = exactly one abstract method** — defaults and statics don't count
- **Lambdas have no type of their own** — target typing supplies it
- **Four shapes:** `Function` (T→R) · `Predicate` (T→boolean) · `Consumer` (T→void) · `Supplier` (→T)
- **`Bi` = two args · `Int`/`Long`/`Double` = no boxing · `UnaryOperator`/`BinaryOperator` = same types**
- **Method references:** static · bound (`obj::m`) · unbound (`Type::m`) · constructor (`Type::new`)
- **Compose:** `Function.andThen` · `Predicate.and/or/negate` · `Comparator.comparing().thenComparing()`
- **Not anonymous classes** — `invokedynamic` + `LambdaMetafactory`; no class file per lambda
- **Non-capturing lambdas are cached singletons** — capturing ones allocate
- **`this` in a lambda = enclosing instance** (anonymous class: itself)
- **Captured locals must be effectively final** — fields are exempt
- **No checked exceptions** in standard interfaces — wrap, define your own, or keep the loop
- **Extract lambdas over ~3 lines** — the stack trace names methods, not `lambda$confirm$2`

### 07 · [The Stream API](../02-language/07-stream-api.md)

- **Streams store nothing and are single-use** — a second terminal op throws `IllegalStateException`
- **Lazy:** nothing runs until a terminal operation; elements flow one at a time through all stages
- **Stateful ops buffer:** `sorted` · `distinct` · `skip` — they break laziness
- **Short-circuiting:** `limit` · `takeWhile` · `findFirst` · `anyMatch`
- **`map` = 1→1 · `flatMap` = 1→many, flattened**
- **Primitive streams avoid boxing** — `mapToInt(...).sum()`, `summaryStatistics()`
- **`peek` may never run** — debugging only, never side effects
- **`toMap` throws on duplicate keys** — always pass a merge function
- **`reduce` identity must satisfy `identity op x == x`**
- **`parallel()` uses the shared common pool** — measure first; never with blocking I/O
- **Close `Files.lines` / `walk` / `list`** with try-with-resources
- **Java 16:** `.toList()` — unmodifiable · **Java 24:** Gatherers for custom intermediate ops

### 08 · [Collectors & Stream Composition](../02-language/08-collectors.md)

- **`Collector` = supplier · accumulator · combiner · finisher · characteristics**
- **`reduce` replaces values · `collect` mutates a container**
- **Combiner runs only in parallel** — a wrong one passes every sequential test
- **`toMap` throws on duplicate keys and on null values** — always pass a merge function
- **`groupingBy` → many values per key · `toMap` → one value per key**
- **`partitioningBy` always has both `true` and `false`** — `groupingBy` omits empty groups
- **Downstream shaping:** `mapping` · `filtering` (9) · `flatMapping` (9) · `collectingAndThen`
- **`filtering` downstream keeps empty groups; upstream `filter` drops them**
- **`teeing`** (12) — two collectors, one pass · **`summarizing*`** — five aggregates, one pass
- **`counting()`**, not `summingInt(x -> 1)`
- **Map factory for ordered keys** — `TreeMap::new` / `LinkedHashMap::new`
- **`Stream.toList()`** (16) — unmodifiable, null-tolerant; the right default

### 09 · [Optional & Null Strategy](../02-language/09-optional.md)

- **`Optional` is a return type** — never a field, parameter, or collection element
- **`of` asserts non-null · `ofNullable` converts** at the boundary
- **Chain with `map` / `flatMap` / `filter`** — every operation short-circuits on empty
- **`flatMap`** when the mapper already returns an `Optional`
- **`orElse` evaluates always · `orElseGet` only when empty** — constants vs computation
- **`orElseThrow(() -> ...)`** — supplier form, so the exception isn't built on the happy path
- **Never `isPresent()` + `get()`** — that's the null check with extra allocation
- **`get()` is a design regret** — use `orElseThrow()` (Java 10)
- **`Optional.stream()`** (9) — `flatMap(Optional::stream)` unwraps many lookups
- **Return empty collections**, never `Optional<List<T>>` and never null
- **Value-based** — never `==`, never synchronise on one, not `Serializable`
- **Rest of the strategy:** `requireNonNull` for params · empty collections · Null Object · nullability annotations

### 10 · [java.time](../02-language/10-java-time.md)

- **Machine time:** `Instant` · `Duration` — **human time:** `LocalDate` · `LocalTime` · `Period`
- **`LocalDateTime` is not a timestamp** — no zone, no point on the timeline
- **Store `Instant`** (or `OffsetDateTime`); convert to `ZonedDateTime` only for display
- **`Period.ofDays(1)`** = same wall clock tomorrow · **`Duration.ofDays(1)`** = 86,400 s
- **`ZoneId` for future events** (DST rules) · **offset for past ones** (what actually applied)
- **DST gap:** shifted forward · **overlap:** earlier offset, or `withLaterOffsetAtOverlap()`
- **All types immutable** — `date.plusDays(1)` returns a new value; discarding it is a silent bug
- **`DateTimeFormatter` is thread-safe** — `static final` is correct (unlike `SimpleDateFormat`)
- **Inject `Clock`** — every `now()` has a `now(clock)` overload; `Clock.fixed` in tests
- **Months are one-based** — use `Month.SEPTEMBER`
- **Precision:** `Instant` nanos, most databases micros — `truncatedTo(MICROS)` before persisting
- **`ChronoUnit.DAYS.between`** for a count; `Period.between` for a calendar description

### 11 · [Java 9–11: Modules, var, HttpClient](../02-language/11-java-9-to-11.md)

- **Modules:** `requires` = readability · `exports` = compile access · `opens` = deep reflection
- **`exports` ≠ `opens`** — frameworks reflecting into private fields need `opens`
- **You feel JPMS even unmodularised** — JDK internals encapsulated by default (16), no `--illegal-access` (17)
- **`--add-opens` is a ticket, not config** — each one names a library to upgrade
- **Split packages and `requires` cycles fail at launch**
- **Automatic module name** from `Automatic-Module-Name`, else the filename — publish it
- **`jlink` works for classpath apps** — ~45 MB runtime vs 200 MB+ JDK
- **`var`** — locals only, needs an initializer, statically typed, **never bare diamond**
- **`List.of` is immutable and null-hostile** — even `contains(null)` throws
- **`Set.of`/`Map.of` iteration order is randomised** per JVM run
- **One `HttpClient` per application** — `static final`; set both timeouts; HTTP/2 by default
- **`strip()` not `trim()`** — Unicode-aware
- **Java 11 removed the Java EE modules** — JAXB et al. become dependencies

### 12 · [Java 14–17: Records, Sealed Types, Text Blocks, Switch Expressions](../02-language/12-java-14-to-17.md)

- **Record** = final, extends `java.lang.Record`, component-wise `equals`/`hashCode`/`toString`
- **Accessors are `amount()`**, not `getAmount()`
- **Compact constructor** — runs before assignment, reassign parameters to normalise
- **Shallow immutability** — `List.copyOf(lines)` in the compact constructor, always
- **Not for JPA entities** — no identity, no mutability, no no-arg constructor
- **`sealed ... permits`** — subtypes must be `final`, `sealed`, or `non-sealed`
- **Runtime-enforced** via the `PermittedSubclasses` attribute
- **Sealed + records = algebraic data types** — each case carries exactly its own data
- **Switch expression:** arrow form, no fall-through, `yield` in blocks, assignable
- **`default` disables exhaustiveness checking** — omit it on enum and sealed switches
- **Text blocks:** closing delimiter sets the indent stripped · `\` joins lines · `\s` keeps a space
- **No interpolation** — use `formatted(...)`; String Templates were withdrawn

### 13 · [Pattern Matching](../02-language/13-pattern-matching.md)

- **Pattern = test + binding** — type patterns, record patterns, nested patterns
- **`x instanceof T t`** — no separate cast, and null never matches
- **Flow scoping:** binding is in scope wherever a match is proven — including after `if (!(x instanceof T t)) return;`
- **`case T t when guard ->`** — guarded cases must precede the unguarded one
- **Dominance is a compile error** — unreachable branches are caught
- **`case Confirmed(var at, var ref)`** — destructure; `var` preferred; `_` for unused (22)
- **Exhaustive over a sealed type = no `default` needed**
- **`default` disables exhaustiveness checking** — omit it
- **Null throws NPE** unless `case null` — never silent
- **Compiles to `invokedynamic`** via `SwitchBootstraps`; destructuring calls accessors
- **`MatchException`** — separate compilation broke an exhaustive switch
- **Polymorphism for open types · pattern matching for open operations** — the expression problem

### 14 · [Java 21–26 Language Features](../02-language/14-java-21-to-26.md)

- **`_` (22):** record components · `catch` params · loop vars · lambda params · resources — **not** fields or method params
- **`_` may repeat in a scope** — it declares no binding
- **Flexible constructors (25):** validate and assign own fields before `super()`
- **Prologue cannot:** read fields · call instance methods · reference `this`
- **`import module java.base` (25)** — lowest precedence; ambiguity errors at the point of use
- **Module imports and compact source files are for scripts**, not application code
- **Compact source file:** implicit class, unnamed package, instance `main`, `java Hello.java`
- **Markdown javadoc `///` (23)** — coexists with `/** */`, one per declaration
- **Java 21 LTS · Java 25 LTS** — the two baselines that matter
- **Still preview:** primitive type patterns · `StructuredTaskScope`
- **Preview class files refuse to load on another JDK** — never in a published library

### 15 · [String Templates: A Post-Mortem](../02-language/15-string-templates-postmortem.md)

- **String Templates do not exist** — previewed in 21 and 22, withdrawn in 23, in no released JDK
- **`STR."..."` will not compile** on any current JDK
- **Use instead:** text block + `.formatted(...)` · `MessageFormat` · parameterised logging
- **The real goal was safety**, not readability — a template carried fragments and values separately
- **Safe construction today:** `PreparedStatement` parameters · serializers for JSON · escaping engines for HTML
- **Preview = no commitment** — may change shape or be withdrawn
- **Preview class files bind to one exact JDK release** — never ship them in a library
- **Track record:** String Templates withdrawn · structured concurrency redesigned after four previews · Vector API incubating since 16
- **Policy:** final only in production · preview in scripts and spikes · never in published artifacts
- **Check the JEP status** before believing any Java article — and distrust undated ones

### 16 · [Generics in Depth](../02-language/16-generics.md)

- **Erasure:** type arguments removed at compile time; `T` → its bound (or `Object`); casts inserted
- **Same class at runtime** — no `List<String>.class`, no `instanceof List<String>`, no `new T[]`
- **Generics are invariant** — `List<Order>` is not a `List<Object>`
- **PECS:** read → `? extends T` · write → `? super T` · both → `T`
- **Wildcards on parameters, concrete types on returns**
- **Capture:** the compiler can't prove two `?` are the same — delegate to a generic method
- **Arrays are covariant and unsound** (`ArrayStoreException`); generics are invariant and checked
- **`@SafeVarargs`** — only when the array is read, never stored or returned
- **Bridge methods** make overriding survive erasure — visible in reflection and stack traces
- **No `static T`** — one class shared across all instantiations
- **Type tokens:** `Class<T>` for simple types · super type token for `List<Order>`
- **Never raw types** — they disable checking for the whole expression, not one argument

## Collections

### 17 · [Choosing the Right Collection](../03-collections/17-choosing-a-collection.md)

- **Four questions:** key-value or values · duplicates · **what order** · concurrent
- **Membership test → `Set`.** If it exists to answer "is this in it", it is a `Set`
- **Range queries → `TreeMap`/`TreeSet`** — `subMap`, `ceilingKey`, `floorEntry`
- **Enum keys → `EnumMap` / `EnumSet`** — array- and bitset-backed, strictly better
- **Queue or stack → `ArrayDeque`** — never `Stack`, never `LinkedList`
- **`HashMap`/`HashSet` order is unspecified** · **`Set.of`/`Map.of` order is randomised per run**
- **`PriorityQueue` iterates in heap order** — only `poll()` is sorted
- **Nulls rejected by:** `TreeSet`, `TreeMap` keys, `ArrayDeque`, `ConcurrentHashMap`, all `of` factories
- **`List.of(...).contains(null)` throws** — it does not return false
- **`unmodifiableList` is a view · `List.copyOf` is a snapshot** — accessors return copies
- **Declare interfaces**, not implementations
- **Size when known:** `HashMap.newHashMap(n)` (19+), `new ArrayList<>(n)`
- **Never:** `Vector` · `Hashtable` · `Stack` (iterates bottom-up) · `LinkedList` by default

### 18 · [List Internals & CustomArrayList](../03-collections/18-list-internals.md)

- **ArrayList growth:** 1.5× — `old + (old >> 1)`; default capacity 10, allocated lazily on first `add`
- **Costs:** `get`/`set` O(1) · `add` amortised O(1) · `add(i,e)`/`remove(i)` O(n) via `System.arraycopy`
- **LinkedList:** ~24 B overhead per node, scattered heap, cache-hostile — prefer `ArrayDeque` for queues
- **Views, not copies:** `subList`, `Arrays.asList`, `reversed()`, `unmodifiableList`
- **Snapshots:** `List.copyOf(...)`, `new ArrayList<>(...)`, `stream.toList()`
- **`List.of`** rejects nulls on read *and* write — `contains(null)` throws NPE
- **`remove(int)` vs `remove(Object)`** — the `Integer` list trap
- **Java 21:** `getFirst`/`getLast`/`addFirst`/`addLast`/`removeFirst`/`removeLast`/`reversed()`
- **Java 16:** prefer `stream.toList()` over `collect(toList())` — but it is unmodifiable
- **`trimToSize()`** — the array never shrinks on its own

### 19 · [HashMap Internals](../03-collections/19-hashmap-internals.md)

- **Index:** `(n-1) & (h ^ h>>>16)` · table length always a power of two
- **Defaults:** capacity 16 · load factor 0.75 · threshold = cap × lf
- **Treeify:** bin ≥ 8 **and** table ≥ 64 → red-black tree; untreeify at 6
- **Resize:** doubles; split by `(hash & oldCap)`; no rehash; order preserved
- **Complexity:** get/put O(1) avg, O(log n) worst (Java 8+); `containsValue` O(n)
- **Nulls:** one null key (bucket 0), many null values; `Map.of` rejects both
- **Sizing:** `HashMap.newHashMap(n)` — Java 19+
- **Memory:** ~32 B/Node (24 B on Java 25 with compact headers) + ~5 B table
- **Not a `SequencedMap`** — that is `LinkedHashMap` and `TreeMap`
- **Keys must be immutable** — mutating a key strands the entry forever

### 20 · [Set, Queue & Deque](../03-collections/20-set-queue-deque.md)

- **Every `Set` is a `Map` underneath** — `HashSet`→`HashMap`, `TreeSet`→`TreeMap`; `EnumSet` is a bitset
- **Dedupe keeping order → `LinkedHashSet`** (or `stream().distinct()`)
- **Set algebra:** `addAll` ∪ · `retainAll` ∩ · `removeAll` − — **all mutate the receiver; copy first**
- **`TreeSet` for queries:** `ceiling` · `floor` · `subSet` — views, O(log n)
- **Queue methods:** throw (`add`/`remove`/`element`) vs special value (`offer`/`poll`/`peek`)
- **`ArrayDeque` for every stack and queue** — circular array, O(1) both ends, **no nulls**
- **`Stack`:** synchronised and iterates **bottom-up** — never use it
- **`PriorityQueue` is a min-heap** — `poll` O(log n), **`remove(Object)` O(n)**, iteration is **heap order**
- **Top-k → min-heap of size k** — O(n log k), then sort the result
- **`EnumSet`** — one `long` for ≤ 64 constants; strictly better than `HashSet`
- **Shared across threads → `BlockingQueue` / `PriorityBlockingQueue`**, never the plain versions

### 21 · [Sequenced Collections](../03-collections/21-sequenced-collections.md)

- **Three interfaces (Java 21, JEP 431):** `SequencedCollection` · `SequencedSet` · `SequencedMap`
- **Methods:** `getFirst` · `getLast` · `addFirst` · `addLast` · `removeFirst` · `removeLast` · `reversed()`
- **Map adds:** `firstEntry` · `lastEntry` · `putFirst` · `putLast` · `pollFirstEntry` · `pollLastEntry`
- **In:** `List` · `Deque` · `LinkedHashSet` · `TreeSet` · `LinkedHashMap` · `TreeMap`
- **Out: `HashMap` and `HashSet`** — no encounter order, so no first or last
- **`reversed()` is a live view** — O(1), writes through, not a copy
- **Independent copy:** `new ArrayList<>(list.reversed())`
- **`addFirst`/`putFirst` throw on sorted collections** — position comes from the comparator
- **`getFirst()` throws when empty · `firstEntry()` returns null**
- **`putFirst` moves an existing key** — an MRU cache in a few lines
- **Retrofitted with default methods** — `getFirst()` defaults to `get(0)`
- **Almost everything derived in `java.util` is a view** — copies say `copyOf`

### 22 · [Immutability & Defensive Copying](../03-collections/22-immutability.md)

- **`final` ≠ immutable** — it fixes the reference, not the object
- **View ≠ copy** — `unmodifiableList` shows the owner's changes; `List.copyOf` does not
- **Recipe:** final class or record · private final fields · no setters · copy in · immutable components
- **Copy in the constructor** — that is where final-field visibility applies
- **Store immutable types** and accessors need no copy
- **Records are shallowly immutable** — `List.copyOf` every collection component
- **Arrays are never immutable** — copy both ways *and* override `equals`/`hashCode`
- **`List.copyOf` is free** when the argument is already immutable
- **Withers** return new instances; the compact constructor re-validates
- **Immutable + properly constructed = thread-safe with no synchronisation**
- **Cost:** O(n) per append to a large immutable collection — use a builder or persistent structure
- **Replace `Date`/`Calendar` with `java.time`** — removes the classic defensive-copy obligation

### 23 · [equals, hashCode & Comparators](../03-collections/23-equality-and-ordering.md)

- **Override `equals` and `hashCode` together** — same fields in both
- **Equal ⇒ equal hash (mandatory) · equal hash ⇏ equal (collisions are legal)**
- **`equals`:** reflexive · symmetric · transitive · consistent · `equals(null)` is false
- **Records generate both from the same components** — the default for value types
- **Hash collections use `hashCode` then `equals` · sorted collections use only `compare`**
- **`BigDecimal("1.0")` vs `"1.00"`:** not `equals`, but `compareTo == 0` — `HashSet` 2, `TreeSet` 1
- **Normalise `BigDecimal` scale** at construction
- **Never compare by subtraction** — overflow flips the sign; use `Long.compare` / `comparingLong`
- **`reversed()` reverses the whole chain** built so far
- **End with a unique tie-breaker** — a `TreeSet` drops compare-equal elements
- **Inheritance + value component in `equals` breaks symmetry** — use composition
- **Never key on `double`, arrays, or mutable objects**
- **`Objects.hash` allocates** — hand-roll or use a record for hot keys

## Concurrency

### 24 · [Threading Fundamentals](../04-concurrency/24-threading-fundamentals.md)

- **`start()` creates a thread; `run()` is just a method call**
- **States:** NEW · RUNNABLE · BLOCKED · WAITING · TIMED_WAITING · TERMINATED
- **`RUNNABLE` includes blocked I/O** — `BLOCKED` means monitor contention only
- **Interruption is cooperative** — a flag plus a convention; running code must check it
- **`InterruptedException` clears the flag** — propagate it, or restore and stop
- **`Thread.interrupted()` clears · `isInterrupted()` does not**
- **`sleep` holds locks · `wait` releases the monitor**
- **Uncaught exception kills one thread silently** — set a handler, always
- **Daemon threads die without `finally`** — never use them for writes
- **Platform thread ≈ 1 MB stack** — pool them, or go virtual
- **`Thread.stop/suspend/resume`** throw `UnsupportedOperationException` since Java 20
- **Name every thread** — thread dumps are unreadable otherwise

### 25 · [Shared State & Synchronization](../04-concurrency/25-shared-state.md)

- **Three problems:** atomicity · visibility · ordering — different fixes
- **`synchronized`:** exclusion + visibility + ordering; reentrant; auto-released on exception
- **`volatile`:** visibility + ordering, **no atomicity** — one writer, value independent of old
- **`count++` is read-modify-write** — `volatile` does not save it; use `AtomicInteger`/`LongAdder`
- **Synchronise reads too** — the lock is what publishes the value
- **Lock on a private final object**, never `this`, never a `String` literal
- **`wait` in a `while`, never an `if`** — spurious wakeups are legal
- **`wait` releases the monitor · `sleep` does not**
- **Deadlock = four conditions** — break circular wait with a global lock order
- **Find it:** `jcmd <pid> Thread.print` — monitors are reported, `ReentrantLock` is not
- **DCL needs `volatile`** or the reference publishes before the constructor finishes
- **Java 24 (JEP 491):** `synchronized` no longer pins virtual threads

### 26 · [The Java Memory Model](../04-concurrency/26-java-memory-model.md)

- **The JMM defines what a read may return** — an abstract contract, not a hardware description
- **Happens-before:** program order · unlock → lock · volatile write → read · start · join · **transitive**
- **Data race** = two accesses, one a write, different threads, no happens-before
- **DRF-SC:** no data races ⇒ behaves as sequentially consistent — the one theorem that matters
- **Volatile piggybacking** — one volatile write publishes every plain write before it
- **Safe publication:** static init · volatile/`AtomicReference` · final field · lock · j.u.c. handoff
- **Final fields freeze at constructor end** — visible however published, *if* `this` didn't escape
- **DCL needs `volatile`** — or use the holder-class idiom and skip it
- **x86 (TSO) forgives, ARM does not** — moving to ARM is a concurrency audit
- **JIT may hoist non-volatile reads** out of loops — infinite loop, legally
- **`long`/`double` may tear** without `volatile` — a spec permission
- **`VarHandle` acquire/release** is for lock-free library code, not applications

### 27 · [Locks, Atomics & java.util.concurrent](../04-concurrency/27-locks-and-atomics.md)

- **Default: `synchronized`** — scoped, auto-released, reported by deadlock detection
- **`ReentrantLock` for features:** `tryLock(timeout)` · `lockInterruptibly` · fairness · multiple `Condition`s
- **`unlock()` in `finally`, always** — nothing else releases it
- **Read-mostly:** immutable map behind `volatile` beats any lock when updates replace the whole value
- **`StampedLock`:** optimistic reads, fastest — **not reentrant**, read into locals, then validate
- **Atomics = one variable, retry not wait** — cannot deadlock
- **`LongAdder` for contended metrics · `AtomicLong` for exact values (IDs)**
- **`updateAndGet` functions may run repeatedly** — keep them pure
- **ABA:** CAS checks equality, not history → `AtomicStampedReference`
- **`CountDownLatch` one-shot · `CyclicBarrier`/`Phaser` repeat · `Semaphore` bounds concurrency**
- **Everything sits on AQS** — one `int` state + a FIFO queue of parked threads
- **Unfair is the default** for good reason — fairness costs throughput
- **Java 24:** `synchronized` no longer pins — revert Java 21-era `ReentrantLock` conversions

### 28 · [Executors & Thread Pool Design](../04-concurrency/28-executors.md)

- **Order:** core threads → **queue** → extra threads → reject — max only matters when the queue is full
- **Unbounded queue ⇒ `maximumPoolSize` is ignored** and memory is unbounded
- **`newFixedThreadPool` / `newSingleThreadExecutor`** — unbounded queue → OOM under overload
- **`newCachedThreadPool`** — unbounded threads → explosion on slow bursts
- **Production:** build `ThreadPoolExecutor` directly — bounded queue, named factory, chosen policy
- **`CallerRunsPolicy`** = backpressure by making producers do the work
- **CPU-bound: size ≈ cores · I/O-bound (21+): virtual threads + `Semaphore`**, no pool
- **`submit` traps exceptions in the `Future`** — consume it, or use `execute`
- **A scheduled task that throws is cancelled silently** — catch inside the task
- **Fixed rate = start-to-start · fixed delay = end-to-start**
- **Bulkheads:** separate pools — or separate semaphores — per dependency
- **Alert on queue depth**, not rejection
- **Never block in `commonPool()`** — shared by parallel streams and `CompletableFuture`

### 29 · [CompletableFuture](../04-concurrency/29-completable-future.md)

- **Completes exactly once** — value, exception, or cancellation
- **`thenApply` = map · `thenCompose` = flatMap · `thenCombine` = zip**
- **`allOf` returns `CompletableFuture<Void>`** — then `join()` the originals, which no longer blocks
- **Default executor is `commonPool()`** — **always pass one for blocking work**
- **Non-async stages run on the completing thread** — or the caller, if already complete
- **Exceptions arrive as `CompletionException`** — unwrap `getCause()` before matching
- **`handle` recovers · `whenComplete` only observes**
- **`cancel(true)` does not interrupt** — the flag is ignored; work keeps running
- **`orTimeout` completes the future, not the work** — `anyOf` losers keep running too
- **Never `join()`/`get()` inside a stage** — pool exhaustion, deadlock
- **Stack traces stop at a pool worker** — the request that started it is gone
- **Still right for:** callback adapters · `anyOf` races · timeouts with fallback · dependent async steps
- **Java 21+:** straightforward fan-out → blocking code on virtual threads

### 30 · [ConcurrentHashMap & Concurrent Collections](../04-concurrency/30-concurrent-collections.md)

- **Design:** per-bin locking — CAS into empty bins, `synchronized` on the first node otherwise; reads are lock-free
- **Atomic:** `putIfAbsent` · `compute` · `computeIfAbsent` · `computeIfPresent` · `merge` · `replace(k,old,new)` · `remove(k,v)`
- **Not atomic:** any sequence of two calls — `containsKey` then `put` is a race
- **No nulls** — keys or values; `get` ambiguity is unresolvable concurrently
- **`size()` is an estimate** — striped counters, `LongAdder`-style; never gate logic on it
- **Iterators are weakly consistent** — never CME, never a snapshot
- **`computeIfAbsent`:** holds the bin lock — no I/O, no other locks, never the same map (`IllegalStateException`)
- **Values:** the map protects the reference, not the object — store concurrent or immutable values
- **Resize is cooperative** — `ForwardingNode` + `helpTransfer`; reads never block
- **Not a cache** — no eviction, no TTL; bound it or use Caffeine
- **Java 24 (JEP 491):** `synchronized` no longer pins virtual threads

### 31 · [Virtual Threads](../04-concurrency/31-virtual-threads.md)

- **M:N** — millions of virtual threads on a few carrier threads (`ForkJoinPool`, FIFO, one per core)
- **Blocking unmounts** — stack copied to the heap, carrier released, resumed later
- **Not faster per task** — more tasks in flight; I/O-bound only, no gain for CPU-bound
- **Never pool them** — `Executors.newVirtualThreadPerTaskExecutor()` in try-with-resources
- **Limit the resource, not the thread** — `Semaphore`, not a fixed pool
- **Connection pools become the visible ceiling** — review sizing after adopting
- **`ThreadLocal` × 1M threads** = a heap problem — prefer `ScopedValue` (final in 25)
- **Pinning:** `synchronized` pinned on 21–23, **fixed in 24 (JEP 491)**; JNI still pins
- **Diagnose:** `jcmd Thread.dump_to_file -format=json` · JFR `jdk.VirtualThreadPinned`
- **Final in Java 21 (JEP 444)** — no `--enable-preview`
- **Don't carry Java 21-era `ReentrantLock` workarounds** into a Java 24+ codebase

### 32 · [Structured Concurrency](../04-concurrency/32-structured-concurrency.md)

- **Subtasks cannot outlive their scope** — the closing brace is the lifetime boundary
- **`StructuredTaskScope.open(Joiner...)`** in try-with-resources — **Java 25 shape**
- **Java 21 `ShutdownOnFailure` / `throwIfFailed` no longer exist** — most tutorials are stale
- **Joiners:** `allSuccessfulOrThrow` · `anySuccessfulResultOrThrow` · `awaitAll` · `allUntil`
- **`join()` throws directly** in the current API — no separate `throwIfFailed`
- **`Subtask.get()` only after `join()`** · **no forking after `join()`** · **owner thread only**
- **Failure cancels siblings** by interruption — non-interruptible native calls still block `close()`
- **Subtasks are virtual threads** — forking a hundred is cheap
- **`ScopedValue` bindings inherit** into subtasks — context without `ThreadLocal`
- **Stack traces keep the fork site** — unlike `CompletableFuture`
- **Thread dumps group by scope** — `jcmd Thread.dump_to_file -format=json`
- **Still preview** — `--enable-preview` at compile and run; never in a shared library

### 33 · [ThreadLocal → ScopedValue](../04-concurrency/33-scoped-values.md)

- **`ScopedValue.where(KEY, v).run(...)`** — bound for the block, unbound automatically
- **No `set`, no `remove`** — immutable binding, lifetime is the code structure
- **`get()` throws when unbound** · `orElse(default)` · `isBound()`
- **Nest `where(...)` to rebind** — shadows, then restores; never mutates
- **`ThreadLocal` leaks:** weak keys, **strong values** — stale entries survive on pooled threads
- **`InheritableThreadLocal` copies per child thread** — a problem at a million virtual threads
- **`ScopedValue` bindings are shared, not copied** — immutability is what makes that safe
- **Subtasks inherit bindings** inside a `StructuredTaskScope`; plain `new Thread(...)` does not
- **The binding is immutable, the object is not** — bind records
- **Still `ThreadLocal`:** mutable per-thread caches — and rethink those under virtual threads
- **Declare `private static final`** · bind only at the boundary
- **Final in Java 25 (JEP 506)** — no `--enable-preview`

## Runtime

### 34 · [Garbage Collection](../05-runtime/34-garbage-collection.md)

- **Trade-off:** throughput · latency · footprint — pick two
- **Serial** tiny heaps · **Parallel** throughput · **G1** default · **ZGC** large heaps + low latency · **Shenandoah** low latency
- **G1 is the default since Java 9** — the silent change when upgrading from 8
- **Set:** `MaxRAMPercentage` · `MaxGCPauseMillis` · `-Xlog:gc*` · `HeapDumpOnOutOfMemoryError`
- **Don't set:** `NewRatio` · `SurvivorRatio` · anything copied from a blog · `UseConcMarkSweepGC` (removed in 14)
- **Pause target is a budget, not a guarantee** — an unachievable one makes things worse
- **Frequency means nothing** — watch the live set after collection and the pause distribution
- **Live set climbing = leak.** No collector setting fixes an application bug
- **Allocation is a TLAB pointer bump** — surviving is what costs, not allocating
- **Humongous = larger than half a G1 region** → straight to old gen, fragmentation risk
- **ZGC:** coloured pointers + load barriers → concurrent relocation, pauses independent of heap size
- **Generational ZGC in 21 · generational Shenandoah in 25**
- **Never call `System.gc()`**

### 35 · [Memory Footprint & Object Layout](../05-runtime/35-memory-footprint.md)

- **Minimum object = 16 bytes** — 12-byte header padded to 8-byte alignment
- **Header:** mark word 8 + class pointer 4 → **8 total with compact headers (Java 25)**
- **Compressed oops:** references are 4 bytes below ~32 GB, 8 above — a **cliff**, not a slope
- **Count objects, not fields** — one fewer object per entry beats four fewer bytes
- **`HashMap` costs ~37 B/entry** before keys and values · `Integer` 16 B · `LinkedList.Node` 24 B + element
- **`Map<Integer,Integer>` vs `int[]`** — roughly 17× for the same information
- **Compact strings (Java 9)** — `byte[]` + coder; ASCII halves
- **Try `-XX:+UseStringDeduplication`** before `intern()` — interned strings are permanent
- **Shallow vs retained** — retained size is what a leak actually costs; MAT's dominator tree
- **JOL** for exact layout · **`GC.class_histogram`** for what is there · **MAT** for what holds it
- **Records are not smaller than classes** — identical layout
- **Footprint is about what survives**, not what is allocated
- **Re-baseline heap sizing on Java 25** — compact headers shrink the live set

### 36 · [Startup, Warmup & Project Leyden](../05-runtime/36-startup-and-leyden.md)

- **Startup ≠ warmup** — time to first request vs time to peak throughput
- **Measure first:** `-Xlog:startuptime` · `-Xlog:class+load` — which phase dominates?
- **Class loading is dominated by verification** — CDS stores pre-parsed, pre-verified classes
- **`-XX:+AutoCreateSharedArchive` (19+)** — the cheap default; self-regenerating
- **AOT cache (24/25):** record → create → use; pre-links **and** replays JIT profiles
- **Archives and caches are tied to the exact JDK** — build them in CI, ship in the image
- **Training run must exercise a real path**, not just startup
- **Short-lived JVM:** `-XX:TieredStopAtLevel=1` + Serial GC — **never** on a long-running service
- **Native image:** milliseconds to start, lower peak, closed world, reflection must be declared
- **Static initialisers run at build time** under native image
- **CRaC** eliminates startup *and* warmup — needs checkpoint coordination
- **Most long-running services should do none of this**

### 37 · [Profiling with JFR](../05-runtime/37-profiling-jfr.md)

- **Run it continuously:** `-XX:StartFlightRecording=settings=default,maxage=6h,maxsize=1g,disk=true,dumponexit=true` — ~1%
- **Dump after the incident** — the rolling window covers the period *before* the dump
- **`jfr summary` first** — the event count distribution names the anomaly
- **`settings=profile` for investigations** — `default` has **no allocation events**
- **Exact:** GC · locks · I/O (above threshold) — **statistical:** execution and allocation samples
- **No contention shown?** Check the event threshold before concluding there is none
- **Custom events** — `extends jdk.jfr.Event`, `begin()`/`commit()`; ~free when disabled
- **No safepoint bias** — unlike anything built on `Thread.getStackTrace`
- **`VirtualThreadPinned`** replaces `-Djdk.tracePinnedThreads`
- **Java 25:** CPU-time sampling (509, experimental) · method timing and tracing (520)
- **async-profiler** for wall-clock, native frames, better flame graphs — it can read `.jfr` too
- **Free and open-source since Java 11** — no licence, no agent

### 38 · [Stream Gatherers](../05-runtime/38-stream-gatherers.md)

- **Gatherer : intermediate :: Collector : terminal** — `stream.gather(...)`
- **Four parts:** initializer · integrator · combiner · finisher
- **Integrator returns `false`** to finish · **`Downstream.push` returns `false`** when downstream is done
- **Return `downstream.push(...)`**, not `true` — propagates short-circuiting
- **Built-ins:** `windowFixed` · `windowSliding` · `fold` · `scan` · **`mapConcurrent`**
- **`mapConcurrent(n, fn)`** — virtual threads, bounded, order-preserving, cancels on failure
- **Use it instead of `parallelStream` for blocking I/O** — never occupies the common pool
- **`ofSequential` for stateful, order-dependent gatherers** — no combiner, never parallelised
- **Finisher runs on exhaustion *and* short-circuit** — that is how trailing windows emit
- **`ofGreedy` is a promise** that the integrator never returns `false`
- **Compose with `andThen`** — name and reuse domain pipeline stages
- **Final in Java 24 (JEP 485)** — preview in 22 and 23

### 39 · [FFM API & Vector API](../05-runtime/39-ffm-and-vector-api.md)

- **FFM final in Java 22** — replaces JNI and `Unsafe` memory access
- **`Arena.ofConfined()` in try-with-resources** — deterministic free, one thread, cheapest checks
- **Arenas:** confined · shared · auto (GC) · global (never freed)
- **`MemorySegment`** — no 2 GB limit, deterministic free, struct layouts, native interop
- **Three checks on every access:** spatial (bounds) · temporal (not closed) · confinement (thread)
- **Use-after-free throws** `IllegalStateException` — not memory corruption
- **`MemoryLayout` + `VarHandle`** — never hand-compute struct offsets
- **`jextract`** generates bindings from C headers
- **`--enable-native-access`** required from Java 24 to avoid warnings
- **`Unsafe` memory methods deprecated for removal (23)** → FFM and `VarHandle`
- **Vector API incubating since Java 16** — needs `--add-modules jdk.incubator.vector`, waiting on Valhalla
- **Check whether the JIT already auto-vectorises** before writing SIMD by hand

### 40 · [The HTTP Client (HTTP/3)](../05-runtime/40-http-client.md)

- **One `HttpClient` per application** — it owns the pool, executor, and SSL context
- **Two timeouts:** `connectTimeout` (client) + `timeout` (request) — setting only one leaves a hung read
- **`followRedirects` defaults to `NEVER`** — set it explicitly
- **4xx and 5xx do not throw** — check `statusCode()`
- **Streaming:** `ofLines` / `ofInputStream` — **must be closed** or the connection leaks
- **`ofString` buffers the whole body** — never for an unbounded response
- **Sync `send` on virtual threads** is the modern default; `sendAsync` for composition only
- **`mapConcurrent(n, this::call)`** for bounded fan-out (Java 24+)
- **HTTP/2:** one connection, hundreds of streams — **pool tuning is irrelevant**
- **Check `response.version()`** — negotiation falls back to HTTP/1.1 silently
- **HTTP/3 (Java 26)** over QUIC — no transport head-of-line blocking, survives network changes
- **No retry, no circuit breaker** — wrap the client; send an idempotency key

## Testing

### 41 · [JUnit 5](../06-testing/41-junit5.md)

- **Three parts:** Platform (launcher) · Jupiter (the model you write) · Vintage (runs JUnit 4)
- **Lifecycle:** `@BeforeAll` (static) → `@BeforeEach` → `@Test` → `@AfterEach` → `@AfterAll`
- **New instance per test method** — `@TestInstance(PER_CLASS)` opts out, reintroducing shared state
- **`assertThrows` returns the exception** — assert on the message too
- **`assertAll`** reports every failure, not just the first
- **Parameterized sources:** `@ValueSource` `@CsvSource` `@MethodSource` `@EnumSource` `@NullAndEmptySource`
- **`@Nested`** groups by precondition; lifecycle nests outward-in
- **Assumption = skip (environment)** · `@Disabled` = skip (broken) — always give a reason
- **`assertTimeoutPreemptively` runs on another thread** — no `ThreadLocal`, no transaction
- **Parallel execution is off by default** — enable in `junit-platform.properties`
- **Migration:** add `junit-vintage-engine`, migrate class by class; `@Test(expected=)` → `assertThrows`

### 42 · [Mockito & Test Doubles](../06-testing/42-mockito.md)

- **Doubles:** dummy · stub · spy · mock · fake — Mockito gives the first four, you write fakes
- **Prefer state verification** — `verify` only for effects invisible from the return value
- **Unstubbed methods return type defaults** — NPE in a mock test means a missing stub
- **Spies need `doReturn().when(spy)`** — `when(spy.m())` calls the real method
- **`void` methods:** `doNothing()` / `doThrow()` — never `when()`
- **Matchers are all-or-nothing** — wrap literals in `eq(...)`
- **Captor to inspect · `argThat` to match**
- **Strict stubs on** — `UnnecessaryStubbingException` and `PotentialStubbingProblem` are real findings
- **`mockStatic` needs try-with-resources** — thread-local, leaks otherwise
- **Mockito 5:** inline mock maker is default — delete `mockito-inline`
- **Never mock:** value objects · types you don't own · the class under test
- **Inject `Clock`** instead of mocking `Instant.now()`

### 43 · [Integration Testing & Testcontainers](../06-testing/43-integration-testing.md)

- **Integration test = crosses a boundary you don't control** — DB, broker, HTTP, filesystem
- **Never H2** as a Postgres stand-in — dialect, error codes, `timestamptz` all differ
- **`@Container` static, not instance** — instance restarts Docker per test method
- **Singleton container + truncate between tests** — the usual large-suite pattern
- **Rollback isolation hides commit-time failures** — constraint violations never surface
- **Set an explicit wait strategy** — the default port check is weak; this is the CI-only failure
- **Never hard-code ports** — `getMappedPort(5432)`
- **Pin image tags**, match the production version
- **Run real migrations in setup** — makes them a tested artifact
- **Assert on SQLState** (`23505` = unique violation), not exception messages
- **`jdbc:tc:postgresql:16-alpine:///db`** — zero-ceremony container from a JDBC URL
- **Awaitility, never `Thread.sleep`** · **`*Test` → Surefire, `*IT` → Failsafe**

### 44 · [Testing Concurrent Code](../06-testing/44-testing-concurrency.md)

- **Testing cannot prove the absence of races** — it raises the probability of exposing them
- **Best technique: less concurrent code** — keep logic pure, confine threading to a few classes
- **Inject executors and clocks** — `Runnable::run` as a same-thread executor in tests
- **Never `Thread.sleep`** — Awaitility or a latch with a timeout
- **Start gate** — a `CountDownLatch` so threads genuinely overlap
- **More threads than cores, many iterations** — warm code past JIT compilation
- **Assert invariants** — conservation, no negatives, no duplicates — not timing
- **`@RepeatedTest` + `@Timeout` on every concurrent test**
- **`ThreadMXBean.findDeadlockedThreads()`** — turn a hang into a named failure
- **jcstress** for memory-model bugs in low-level primitives — not application code
- **Flaky concurrent test = probable real race** — quarantine and reproduce, never retry-until-green
- **Test on production-like hardware** — core count and ARM change what reproduces
